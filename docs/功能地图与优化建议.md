# 功能地图与优化建议

> **快照**：2026-11-03 · 基线 `20434ab` + 「返回键 / 诊断导出 / 白屏兜底」未提交改动
> **本文性质**：功能全貌 + 优化意见，**分析类文档，不承担进度状态**。
> 「做到哪、接下来做什么」仍以 `docs/开发进度与待办.md` 为唯一入口；两边冲突时以那份为准。

---

## 0. 一句话结论

能力已经齐了（学、练、弹、测、导入、上架准备都有），短板不在「还能做什么功能」，
而在**从「打开 App」到「弹完一首」之间的坡道**：首屏太重、曲库没阶梯、练完不给下一步。

---

## 1. 功能地图（五层）

```
① 入口       今日 · 学习 · 练习 · 曲库 · 我的    ＋ 设置抽屉（节拍器 / 模拟键盘 / 连接 / 主题 / 诊断 / 曲库包）
                 │
② 四条能力线  学习主线 │ 乐理练习 │ 曲库与内容 │ 输入与设备
                 │
③ 判定内核    音高八度严格 · 音长只观察 · 节拍 0.25 拍容差 · 连音线 / 弱起 / 反复 / 三连音 / 和弦识别
                 │
④ 账本与数据  theoryPath（课时）· skillLedger（技能）· practiceStats（题型）· practiceLog（记录）· 指标 · 备份
                 │
⑤ 质量底座    889 例单测 · 67 项 headless · CI 四 job · 版本/图标/字体脚本 · Android + iOS 原生工程
```

### 1.1 入口与导航

| 分区 | 里面有什么 | 位置 |
|---|---|---|
| 今日 | 「下一步」主卡（`nextStep.ts` 唯一判据）、今日状态与连续天数、复习提醒、学习路径 rail、视奏/识谱/错题本三个工具入口 | `src/ui/HomeView.vue` |
| 学习 | 识谱主线（L1 / L2 / L3 三条课程线）+ L3 预备 | `LearnView.vue`、`ReadingView.vue`、`L2ReadingView.vue`、`L3ReadingView.vue`、`L3PrepView.vue` |
| 练习 | 乐理地图 35 节、错题本重练 | `PracticeView.vue`、`ReviewView.vue` |
| 曲库 | 15 首 17 编配、搜索筛选、跟弹、整曲评测、外部包 | `RepertoireView.vue`、`PackageManager.vue` |
| 我的 | 练习统计、最近 7 天、指标导出、档案备份 | `MeView.vue` |

页面不是路由，是 `App.vue` 里的 `screen` 状态机（12 个值）+ `returnTo` 单一返回目标；
返回键在 Android 上按「抽屉 → 上一页 → 今日 → 退出」逐层消费（`src/back-button.ts`）。

### 1.2 四条能力线

**A · 学习主线**（`src/ui/` + `src/domain/`）

建档自评（3 题）→ 识谱 L1 单手五键 / L2 六课 / L3 和弦四课 → 各档过关测试 → 视奏生成（消耗式题库，一条最多 2 遍）→ 曲库跟弹（分段 / 整曲）→ 整曲分段评测 → 复盘（错音、节奏偏差三色标注）→ 错题本重练。

**B · 乐理练习**（`src/practice/`，4.7k 行）

35 节 = 基础十关（Q1–Q10）+ L3 预备 9 节 + L4 / L5 各 5 节 + L6 6 节；10 种题型（单音 / 符号 / 音程 / 和弦 / 临时升降 / 和弦进行 / 音型 / 旋律听辨 / 分解和弦 / 手位读谱）。
每题一句结论 + 两步判读的讲解（`explanation.ts`）；弹奏作答三路共用 `onPlayNote`；节拍跟弹网格；旋律题先听判调性、答完揭谱照谱跟弹。

**C · 曲库与内容**（`src/repertoire/`，4.0k 行 + 作者脚本）

目录按 `songId` 聚合多编配、按引擎评级排序、到期下架；曲库页搜索 / 档位筛选 / 缺技能清单 / 同歌升级；外部包安装卸载（`minAppVersion` 硬校验）；MusicXML 与 `.mxl` 导入；作者 CLI：`validate:content` / `build:catalog` / `import:musicxml` / `import:batch` / `export:demo`。

**D · 输入与设备**（`src/midi/`，1.1k 行）

四路输入：USB MIDI（Web MIDI）、BLE MIDI（App 走原生插件、浏览器走 Web Bluetooth）、电脑键盘模拟、88 键屏幕琴键。
解码只有一份 `bleCodec.ts`，平台判断只有 `src/platform.ts`；错误统一 6 码；连接诊断可一键复制；未捕获异常收进一张可复制的卡片（`src/app-errors.ts`）。

### 1.3 判定内核（所有练习共用同一把尺子）

| 口径 | 规则 | 唯一来源 |
|---|---|---|
| 音高 | 八度严格（`C4 ≠ C5`） | `domain/pitch.ts` |
| 音长 | **只观察不判错**，按住比 ≥ 0.6 记为「按住」 | `domain/hold.ts` |
| 节拍 | 按拍算，容差 0.25 拍 | `practice/rhythm.ts` |
| 连音线 | `tie` 合并在派生层，延音处不重新击键 | `domain/tie.ts` |
| 弱起 | 首小节实际拍数，事件流仍从第 0 拍算 | `domain/pickup.ts` |
| 反复 | `playOrder` 展开嵌套反复与 D.C./D.S. | `domain/repeats.ts` |
| 三连音 | 3:2 组 id，`noteBeats()` 统一折算 | `domain/tuplets.ts` |
| 和弦 | 3–5 音、允许八度重复，识别性质与转位 | `domain/chords.ts` |

### 1.4 账本与数据

三本账各管一件事，互不越界：`theoryPath`（课时完成态与最好成绩，过关只写这里）、`skillLedger`（跟弹写 learning、过关写 passed）、`practiceStats`（按题型计数，只统计不写过关）。
另加 `practiceLog`（练习记录，含放弃点）与 `metrics.ts`（最近 30 天时长 / 放弃点 / 缺口命中率）。
**本地优先**：不做账号与云同步，换设备靠 `我的 → 学习档案` 导出/导入 JSON（`storage/backup.ts`）。

### 1.5 质量底座

| 层 | 现状 |
|---|---|
| 单元测试 | 889 例 / 89 文件，覆盖判定口径、渲染、导入、内容包、档案、BLE、内容 QA |
| 视觉验收 | 6 个脚本 / 67 项，`npm run verify:all` 一条命令起停 dev server |
| CI | 4 job：`check`（版本 / 图标 / 构建 / 单测 / 内容 QA / catalog 幂等）、`headless`、`android`（debug APK + 未签名 AAB）、`ios`（模拟器关签名编译） |
| 发布脚本 | `version:sync`（web + 双端版本号）、`icon:gen`（30 个图标与启动图）、`fonts:fetch`（自托管字体） |
| 原生工程 | `android/`、`ios/` 就位，2 个 Capacitor 插件（BLE + App） |

## 3. 优化建议

### A · 立刻做（本周，高价值低成本）

| # | 事项 | 为什么 | 做成什么样（验收） |
|---|---|---|---|
| A1 | **首屏拆包**：`notation/renderScore` 改动态 `import()` | 主 chunk 2045 KB / gzip 469 KB，VexFlow 全量在主包里；首页与自评根本不需要画谱，低端安卓冷启动要白白解析这两兆 | `npm run build` 主 chunk < 600 KB；首页与自评不请求渲染分包 |
| A2 | **曲库按「能不能弹」排序** | `skillLedger` 与缺技能清单都算好了，但列表仍按评级排——L4 用户第一屏看到的是 L6 | 列表分三段：「现在能弹 / 再练 N 个技能 / 还早」；缺技能直达微课的入口出现在列表层而不是详情层 |
| A3 | **跟弹结束给一句下一步** | `ScoreFollow` 已记错音与小节，`nextStep.ts` 会调度，但两者没接上，用户看到分数就结束了 | 结束卡片出现「第 7 小节和弦最常错 → 去 L6-6」并可直接跳转 |

### B · 排期做（2–4 周，决定留存）

| # | 事项 | 为什么 | 做成什么样 |
|---|---|---|---|
| B1 | **曲库阶梯化** | 14/15 首只有一个档位。用户「想弹这首」时只看到一个太难的版本，或者觉得太幼稚 | 先给 5 首各补一个低两档的编配（L3/L4）；`catalog.json` 里 ≥6 首有 2+ 编配；同歌升级继承开始有真实用户 |
| B2 | **真机验收 + 上架** | 代码侧没有阻塞项了，这是唯一挡住「落地」的动作 | `docs/移动端-BLE接入.md` 8 步全过；商店素材（截图、蓝牙用途说明、隐私政策）齐备 |
| B3 | **档案自动备份** | 本地优先的硬伤：卸载 / 清数据即丢全部进度，用户毫无预警 | 用 Filesystem 每周往应用外部目录写一份（Android 系统备份可带走），或「我的」页首次进入即提示导出 |

### C · 顺手清理（穿插做）

| # | 事项 | 说明 |
|---|---|---|
| C1 | 复盘标注音长偏差 | `hold.ts` 已有 `MIN_HELD_RATIO`，但目前只在判题时当观察项；L5+ 用户把音弹短照样满分，复盘一个字不提。建议只标注、不判错 |
| C2 | 拆三个大组件 | `RepertoireView` 1803 / `PracticeView` 1800 / `App.vue` 1561 行；把「跟弹会话」（音频 + 判定 + 分段 + 写账本）抽成 composable，否则下一步加功能只会更肿 |
| C3 | 练习回执文案统一 | 「停留时长」与「答题数」两套口径已在文案上分开，但指标卡里仍并列，容易被读成同一套练习量 |

### D · 明确不做（现阶段）

| 事项 | 判断依据 |
|---|---|
| 麦克风拾音识别 | 声学钢琴识别稳定性不足，且与「有 MIDI 才判题」的产品假设冲突 |
| MIDI 文件自动编配 | 需要人工审核环节，边际收益低于把现有曲子做阶梯 |
| 全局搜索与深链 | 只有 web 版有 URL 时才有价值；App 内五分区已够短 |
| 账号与云同步 | 已决策本地优先（`docs/本地优先与设备迁移.md`） |
| 更炫的示范动画 | 先「对、自然、能教学」，不做影视级表现力 |

### 优先级矩阵

| | 成本低 | 成本高 |
|---|---|---|
| **价值高** | A1 首屏拆包 · A2 曲库排序 · A3 下一步回执 | B1 曲库阶梯化 · B2 真机验收上架 · B3 档案备份 |
| **价值低** | C1 音长标注 · C2 拆组件 · C3 文案统一 | D 组：拾音 / 自动编配 / 深链 |

## 4. 如果只做一件事

- **代码侧**：A1 + A2。它们不动产品逻辑，却直接决定新用户第一次打开看到的是「两首能弹的歌」还是「两兆 JS 加一堆 L6」。
- **推进侧**：B2 真机验收。跑完 8 步把「复制诊断信息」的文本贴回来，按实际问题改，而不是继续加功能。
- **内容侧**：B1 阶梯化。别再加单档新歌——《欢乐颂》那条 L2+/L3+/L4+ 的阶梯才是这个 App 该有的样子，而它目前是孤例。
