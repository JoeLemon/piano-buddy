# UI 重构说明（2026-10）

> 目标：让「打开 App 之后该干什么」只有一个答案，让每个控件的归属只有一处。

## 一、改之前的问题

| # | 问题 | 表现 |
|---|------|------|
| 1 | 首页六个同级按钮 | 先认谱 / 5 分钟视奏 / 曲库 / 乐理 / 错题 / 自评平铺，用户得自己判断先后；自评还被压成一条下划线小字 |
| 2 | 顶栏信息过载 | MIDI 状态 + 模拟键盘 + 节拍器（含滑块）+ 主题 + 连接诊断 + 键盘映射长提示，全部常驻，每个界面都在抢注意力 |
| 3 | 返回语义单一 | 任何页面的「返回」都回首页，没有「上一级」概念，也没有面包屑 |
| 4 | 标题重复 | 壳层给一次 h1，曲库页自己又给一次；自评页出现「自评 + 三道自评」两行标题 |
| 5 | 判断逻辑写在视图里 | 「下一步该练什么」散落在 `HomeView` 的 v-if 与 `App.onOpenReading` 的分支里，改路径要动两处 |
| 6 | 样式各写一套 | 每个视图重复定义 h1、按钮、卡片；圆角 6px 与 999px 混用，边框色 `--pb-border`（近黑）与 `--pb-border-soft` 混用 |
| 7 | 视奏页控件与谱面争位 | 手选 / 指法 / 速度排在谱面之前，谱面被推到屏幕下半部分 |

## 二、改成了什么样

### 1. 功能架构：四个分区 + 一个「下一步」

```
今日（仪表盘）  课程（识谱/视奏/过关/复盘/ L3 预备）  曲库  乐理
```

- `src/domain/nextStep.ts` 成为唯一判据：
  - `nextAction(profile)` → `{ kind, eyebrow, title, detail, cta, goal }`
  - `learningPath(profile)` → 四段路径 `done / current / todo`
  - `handState` / `sightUnlocked` 提供给工具行
- `App.vue` 只负责把 `kind` 映射成切屏：`placement → 自评`、`lesson/test → 识谱`、`sight → 视奏`。
- 分支顺序有一个坑：过完 L2 后 `lessonId` 仍停在 `L2-test`，所以 `nextAction` 必须先看 `l2Passed`，
  否则会一直提示重考。同理 `onOpenReading` 在 `l2Passed` 时回到 L2-6 复习，而不是再考一次。

### 2. UI 交互：浏览态 / 沉浸态

- **浏览态**（今日 / 曲库 / 乐理 / L3 预备 / 自评）：顶栏显示分区导航，可自由跳转。
- **沉浸态**（识谱 / 视奏 / 过关测试 / 复盘）：导航收起，只留 `← 分区名`，避免练习中误点。
- **顶栏只留三样**：设备状态 chip（未连接时就是「连接键盘」按钮）、节拍器 chip、设置。
  模拟键盘、节拍器速度滑块、主题、连接诊断、键盘映射说明全部进右侧设置抽屉（Esc 关闭）。
- **标题唯一**：顶栏左侧只显示分区名（课程 / 曲库 / 乐理 / 开始），页面标题由视图自己的 h1 承担；
  壳层用 `show-heading` 控制，避免曲库、复盘、自评出现两行标题。

### 3. 页面级重排

- **首页**：主卡（标题 + 可选一句说明 + 进度 chip + 主按钮）→ 学习路径时间线 → 入口（5 分钟视奏 / 先认谱 / 曲库 / 乐理 / 错题）→ 自评入口。
- **自评页**：三道题各一张卡片，右侧 `会 / 还不会` 分段控件，底部「已答 n/3 + 提交」。
- **视奏页**：谱面提到控制条之前；手 / 指法 / 速度 / 听一遍收进一条工具栏，听一遍靠右。
- **乐理页**：L3 预备课入口从「像输入框的按钮」改成左侧强调条的入口卡。

### 4. 设计令牌与共享样式

`src/ui/tokens.css` 现在分三层：令牌（颜色 / 间距 / 圆角 / 层级 / 动效）→ 基调（背景、排版、`.surface` 卡片）→ 控件（`.segments` 分段、`.dot` 状态点）。
`.surface` 由全局提供，AppShell 不再用 `:deep` 给每个页面套一层卡片样式。

## 三、第二轮：布局重排（2026-10-22）

第一轮解决了「点什么」，第二轮解决「摆在哪」。逐屏截图后发现的共性问题：

| 现象 | 原因 |
|------|------|
| 每页都要往下滚｜首页 6 个入口堆成一条长列，1440×960 都放不下 | 单列 + 54rem 画布，宽度浪费 35% |
| 谱面上下各空 100~200px | VexFlow 画布固定 280 / 420，实际内容只占中间一条 |
| 三小节谱面出现横向滚动条 | 小节宽度写死 360/240，不随容器缩放 |
| 自评三题拉成一整行，控件飘到最右 | 行内 `space-between`，宽度越大越割裂 |
| L3 五张课卡挤成 4+1 | `minmax(9.5rem)` 在 808px 内容宽下只放得下 4 列 |

对应改动：

1. **画布 64rem**：`--pb-max-width` 54rem → 64rem，顶栏 / 分区导航 / 内容区同一宽度。
2. **谱面自适应**（`src/notation/renderScore.ts`）：
   - `fitScale()` 按容器可视宽度等比压缩小节宽度，下限 0.72（再窄保留滚动，免得音符挤在一起）；
   - `trimCanvas()` 用 `getBBox()` 裁掉上下留白（各留 12px）。VexFlow 同时写 `viewBox`、`height` 属性与内联 `style`，三处必须一起改，否则会被另一处按比例缩回去（谱面会变小并居中）。
   - 效果：单手谱面块 287px → 109px，双手 430px → ~210px，三到四小节不再横向滚动。
3. **首页两栏**（≥900px）：主卡通栏；下方「学习路径」竖排时间线在左、「想换个练法」在右；工具行改成「标题 — 说明 — ›」一行，窄屏才折成两行。
4. **自评页三栏**（≥760px）：三道题并排成卡片，分段控件贴内容宽度并压到卡片底部，三张卡的按钮横向对齐。
5. **曲库页**：播放条（播放 / 重播 / 指法 + 速度 + 手）移到谱面**上方**，进度与拖动条留在谱面下方——先能听，再看谱。
6. **乐理 / L3**：选项在 ≥720px 分两列；L3 课卡 `minmax(8.2rem)` 五张一行；L3 课内块去掉描边，改成上边框分区，减少「盒中盒」。
7. **识谱 / L2**：键盘图收进浅底面板居中，和谱面分开，读谱时不被抢注意力。

## 四、第三轮：做减法（2026-10-22）

前两轮是在「加」：加分区、加路径、加两栏。这一轮只删，原则是**如无必要勿增实体**——一个信息只说一次，一个动作只有一个入口。

删掉的重复与解释：

| 位置 | 删了什么 | 为什么 |
|------|----------|--------|
| 首页主卡 | `eyebrow`（「L1 识谱课」）、课中 `detail` 一句指导语、四个入口的说明句、「右手已解锁 · 左手未解锁」 | 标题已含级别；进度 chip 已含数量；课内正文会讲这些；手的状态在路径里 |
| 首页路径 | `待开始` / `随时可听示范` 这类空状态文案 | 没内容就不占位 |
| 自评页 | `开始之前` 小标签、三题的解释行、「已答 n/3」 | 问题本身够清楚；底部错误提示已说明未答完 |
| 识谱 / L2 / 视奏 | 重复的「连接 MIDI 键盘」按钮（顶栏已有常驻入口） | 一个动作一个入口，文案改成指向右上角 |
| 识谱 / 视奏 | 三行开场提示压成一行 | 提示只值一句 |
| 视奏 | 「准备 / 演奏中」小标签、无 MIDI 时的占位破折号 | 文案本身已表明阶段 |
| 曲库 | 导语、`N 个编配` 计数、与 h2 重复的 eyebrow、`ScoreProgress`（与可拖进度条重复） | 编配卡片本身就是计数；位置只需要一个指示 |
| 乐理 | 整段导语、题头类型标签（与选中 tab 重复）、内容来源的免责长句 | 同上 |
| L3 预备 | 整段导语、`L3 预备课 · id` 小标签、进行中/已完成徽章、覆盖技能行、题头小标签 | 与课卡状态、课内 h2 重复 |
| 复盘 | 「回首页」按钮 | 顶栏返回箭头已经是同一个动作 |
| 设置抽屉 | 三个分组小标题、两段说明、抽屉里重复的节拍器开关 | chip 自己带状态文字（「模拟键盘 开」）；节拍器关着时只给一个「打开节拍器」 |

顺带修的三处视觉：

1. 大谱表每个小节都画一个花括号 → 只在行首画一次（`addConnector` 收进 `index === 0`）。
2. 滑块全站统一为细轨道 + 强调色圆点（`tokens.css` 里一套 `input[type=range]` 样式），不再各浏览器一套。
3. 键盘图面板改成贴合内容宽度并居中，不再是一条横贯卡片的浅色带；奇数个入口时最后一条占满整行。

**保留的文案**是测试当契约用的那些（如「视奏里只会用到已经认过的五个音，先把它们认准。」「L2 也过了」「先认谱」「请连接 MIDI 键盘」「这条还能练 n 遍」），删改前先 grep 测试断言，改完逐屏截图核对了 11 个状态的两档宽度。
