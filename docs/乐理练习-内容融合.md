## 逐题讲解（2026-10-23）

`src/practice/explanation.ts` 给六种题型（单音 / 音程 / 和弦 / 进行 / 音型 / 旋律）生成「一句结论 + 两步判读」，`PracticeQuestion.explanationSteps` 携带，练习页渲染成讲解卡（结论头 + 判读步骤列表）。符号与临时升降仍用各自内容里写好的讲解。

| 题型 | 结论 | 判读步骤 |
| --- | --- | --- |
| 单音 | 这个音落在某谱的某线/间 | ① 先认谱号锚点（高音谱 C5、低音谱 C3）② 按音高方向数到符头 |
| 音程 | 几度、几个半音 | ① 数字母得度数 ② 数半音定性质 |
| 和弦 | 根音往上叠哪些三度 | ① 找根音按三度叠置 ② 对半音结构（如 `0 / 4 / 7`） |
| 进行 | 对应哪组级数 | ① 先看调 ② 逐个和弦定位级数 |
| 音型 | 走向名称 | ① 首尾看方向 ② 逐音比较相邻关系 |
| 旋律 | 哪个调 | ① 开头主和弦给调 ② 结尾音确认 |

要点：

- 所有事实（音程半音数、和弦叠置结构、进程级数、旋律主和弦）都从目录数据取，不写死；改目录不会让讲解跟着错。
- 谱面位置由 `staffPlacement(clef, pitch)` 按音级算出（支持上下加线），18 个单音题库条目逐条有测试覆盖——**这里算错就是教错**。
- 「数线间的方向」按音高判断：高音谱 C4 在锚点 C5 下方，不能说「往上数」。

## 弹奏作答（2026-10-24）

练习页顶部有「作答：选项 / 弹琴」。选「弹琴」后，题目不再给四个选项，而是直接在琴上弹出答案——**答案就是谱面上画的音**，所以判题从 `question.staff` 推导（`src/practice/playAnswer.ts`），题库里不存第二份答案。偏好写进 localStorage（`piano-buddy-practice-answer`）。

| 题型 | 怎么算答对 | 判定方式 |
| --- | --- | --- |
| 单音 | 弹出这个音（八度严格） | 一个音，弹对即判 |
| 音程 | 把两个音都弹出来 | 集合相等，先后不限 |
| 和弦 | 把和弦音全弹出来 | 集合相等，先后/转位不限 |
| 音型 | 按谱面顺序逐个弹出 | 顺序相等（含同音重复） |
| 符号 / 临时升降 / 进行 / 旋律 | — | 没有唯一该弹的音，自动回落到选项并说明原因 |

规则细节：

- **边弹边判**：多音题弹到一半是「已弹 1 / 2」的中间态，不是答对；出现不属于答案的音（或音型题顺序错）立刻判错，并说出多弹了哪个音。
- **只算一次分**：答完后再按键只是试弹，不改判定。
- **「音名对了、八度不对」单独点名**：单音题最常见的错法，反馈写「谱面是 C4，你弹的是 C5——音名对了，八度不对」，同时把琴键滚到正确音上，让学生直接看见差一个八度。
- **弹琴时题面文字隐藏**（只留给读屏）：单音题的 `prompt` 就是音名，摆在谱面旁边等于给答案。
- 三种输入共用一条判题路径：屏幕琴键（`KeyboardDiagram` 的 `note` 事件）、MIDI 硬件（`subscribeMidi`）、电脑键盘（模拟键盘模式，D 键=当前音区 C）。`source` 只决定声音从哪来。

## 节拍与跟弹（2026-10-24）

音高判对只说明「认出了这个音」。练习页现在也管时间：`src/practice/rhythm.ts` 把每个目标音放到时间轴上，判实际落点离目标有多远。

**时间一律用「拍」而不是毫秒。** 容差 1/4 拍，80bpm 下约 190ms，正好容得下初学者起手的抖动；换速度时容差跟着缩放，60bpm 与 120bpm 的判定口径才一致。每个击键归到它想打的那个音（`RhythmHit.slotIndex`），同一个音弹几次只认第一次——反复试按不该被当成「越弹越准」。

### 旋律跟弹

旋律题下面有「跟弹」：先听一小节预备拍，倒数结束才开始算时间。网格上一格一拍、粗线是小节线，目标音的音名压在拍线上；弹对了落绿点、偏了落红点、漏了留一个空心灰圈。三者都以拍线为中心，所以「对不齐」本身就是「没弹在拍上」的证据。

- **八度严格**（沿用 `melodyMatch`，与曲库跟弹 `pitchEqual`、弹奏作答 `playAnswer` 同一口径）：谱面上写了哪个八度就该弹哪个八度；无谱面时期的「只比音名」降级口径已废弃。
- **弹错音不推进进度**：混过去只会让后面一路错位，所以那一下只提示「这个音不对」，位置留给正确的音。
- 拍点按事件自己的 `timeMs` 算，不依赖渲染帧——帧率抖动不该变成判定误差。
- 结论只说整体：`音高与节拍都对了 8 / 9 音（89%）；整体没有系统性偏移。`逐音偏差网格上已经画出来了，再用文字重复一遍是噪声。
- 跟弹**不进关卡计分**：旋律题的主任务仍是听辨调性，跟弹是附加练习。

### 音长（2026-10-25）

`note-off` 到达后按每个音的目标时值比一次：短于六成（`MIN_HELD_RATIO`）在结论里追加一句「N 个音按得太短，长音符要按住不放」。**只观察、不判错**——连音、保持音在不同教材里口径不一，拿它判对错会误伤正确的演奏；而初学者最普遍的毛病（全音符弹成四分音符）用一句话就点得出来。

同一拍上左右手时值经常不同（低音铺满全小节、右手走四分音符），所以 `RhythmSlot` 记每个音自己的目标时值（`targetBeats`），不拿最长的那一个要求所有音——这是实现时真实踩到的坑：最初按槽位的 `beats`（取 max）判，把「短音准时抬手」的正确演奏说成了弹短。

三种输入都发 `note-off`：硬件 MIDI、电脑键盘（keyup）、屏幕琴键（pointerup）。抬手要配到「最近一次按下这个音且还没松」的那一击上，不能限定当前槽位——初学者常按住一个音等下一个音，抬手时进度早就往前走了。

**同一把尺子也量视奏复盘**（2026-10-25 续）：阈值搬到 `src/domain/hold.ts`，跟弹与 `domain/compare.ts` 共用。`SightView` 现在也记 `note-off`，复盘页统计行下方多一行「N 个音按得太短，长音符要按住不放。」——只观察：不影响过关判定、不进错题本、谱面上不多一种颜色。和弦谱按事件逐个音判，按错的音不参与。

### 音型题的时值

音型题本来就有节奏（谱面上是四分音符），所以弹奏作答也记时刻。答完后多一行灰字：`节拍：1 / 4 个音在拍上。整体偏晚。`

**时值不影响对错**：音高弹对就是答对，节奏是附加观察。这样既不动既有判分口径，也让学生看见「音对了但没按谱面的时值弹」。单音、音程、和弦没有节奏可言，不显示这一行。

### 输入

跟弹自己订阅 MIDI（硬件 + 电脑键盘），同时也接受练习页推上来的屏幕琴键按键（`NotePulse`）——跟弹看不到屏幕琴键的点击，这条支路必须补。两者可能收到同一个事件对象，按引用去重，所以屏幕琴键一下不会被判两次。

### 曲库也用同一块网格（2026-10-24 晚）

曲库的「跟弹本段」不再跳视奏页，就地展开 `ScoreFollow.vue`，复用同一块 `RhythmGrid`。判定层因此扩了一档：`planForScore(score, hand)` 直接读谱面生成时间轴，**同一拍上的左右手与和弦合并成一个槽位**，`gradeRhythm` 也改为按槽位收集多个按键（弹齐才算过，多按的音不算）。

网格上多音槽位只写最高音 + `+N`（还要多按几个键）——三四个音名挤在一格里会连隔壁格子的数字一起盖住。谱面与示范播放器跟着切到这一段，保证「看的、听的、判的」是同一份音符。细节见 `docs/二期-曲目学习路径.md` §7.6。

## L4 预备课（2026-10-25 追加）

乐理地图第三章，配合 L4 编配（分解和弦织体、手位两端扩张），不锁、随时可练：

| 关卡 | 题型 | 内容 | 题量/通过线 |
| --- | --- | --- | --- |
| L4-1 | `broken` | 分解和弦是什么和弦 | 5 / 4 |
| L4-2 | `handSpan` | 最两端跨几度 | 5 / 4 |

- **分解和弦题全部从和弦题库派生**（`src/practice/brokenChordContent.ts`）：根音、拼写、类型沿用 `CHORD_EXAMPLES` 同一份数据，「分解」与「柱式」听到的是同一组音——两份内容永远不会不一致。谱面上每个音单独一组四分音符；试听有「听一听（分解）」与「柱式」两个入口（`QuestionStaff` 的 `blockListen`），柱式把几个音合成一个全音符事件（`practiceScore.ts` 的 `blockScore`）。
- **手位读谱 12 条例子**（`src/practice/handSpanContent.ts`）：五度对照 3 条、六度 4 条、七度 2 条、八度 3 条，含 2 条低音谱；全部自然音，不掺升降号噪声——这题数的是级数，临时记号只会添乱。`diatonicSpan(low, high)` 数字母数级数；干扰项取 ±1/±2/±3 内的另外三个跨度（答案是八度时上下都要有，所以 deltas 要正负交替试）。
- **讲解三步**（`explanation.ts`）：分解和弦「把音拢到一块 → 按三度叠回去 → 拿不准对照柱式」；手位「只看最两端 → 数字母 → 五度内外下结论」。所有事实从目录数据取，不写死。
- 自由练习同步多出「分解和弦」「手位读谱」两个页签；曲库缺 `texture.broken` / `pos.expand` 时，「去上课」直达 L4-1 / L4-2（`skillRoutes.ts` 的 stage 路由 + `PracticeView` 的 `focusStageId`，进页即开课，不用再点地图）。
- 顺带修掉一个潜伏 bug：3 个四分音符的音型题填不满 4/4，VexFlow STRICT 模式抛 `IncompleteVoice`，谱面一直渲染不出来。现在 `renderScore` 按已用拍数贪心补休止符（`restTokensFor`）。

## 练习统计（2026-10-25 追加）

普通练习从此也留痕——但只留趋势，不留明细：

- `Profile.practiceStats` 是 `Record<题型 id, { answered, correct }>`。每次作答写一笔，选项与弹奏共用 `settleAnswer` 这一个入口，口径不会分叉；父组件顺序应用每次 emit，快速连答不丢。
- 随档案迁移：`mergeProfile` 只做结构校验（计数非负整数、答对数夹回答数、坏形状整条丢弃）。认不出的题型 id 天然无害——读取方按当前题型查表，对不上就不显示。
- **只写计数，不写技能 `passed`**：一次答得好不构成过关，关卡结论仍由 `recordTheoryResult`（通过线）与技能账本两条既有通道出。
- 界面两处：练习页答题区与小结各一行「这个类型累计 M%（c / a）」；「我的」页练习记录多一行「乐理答题：共 N 题 · 正确率 M%」。

## 旋律谱面化（2026-10-26 追加）

旋律题做成**两阶段**：先「听旋律判断调性」（4 个调性选择题），答完即揭谱；再用 `MelodyFollow` 照着同一份谱面跟弹。

- **谱面与试听同源**（`melodyPlayback.ts`）：`melodyStaff(question)` 把主音和弦放第一小节（听辨调性的锚点，3/4 用 3 拍、4/4 用 4 拍满小节），旋律从第二小节起按拍分小节；`melodyToScore` 直接由它派生 `Score`，不另存一份音符数据——听到的、看到的、判的永远是同一组音。`QuestionStaff` 复用现有 `renderScore` / `previewScore`，旋律走 `melody` 分支，不引入新渲染管线。
- **跟弹口径八度严格**（`melodyMatch`，与曲库跟弹 `pitchEqual`、弹奏作答 `playAnswer` 一致）：谱面写了哪个八度就该弹哪个；无谱面时期的「只比音名」降级口径已废弃。弹错音不推进进度，混过去只会让后面一路错位。
- **「先听再看」**：启用后谱面藏起、期间自动播放旋律，答完调性才揭谱——不让调性直接从谱上数出来（`PracticeView` 的 `setListenFirst` 只改 `revealed`，答完 `settleAnswer` 立即揭谱，不靠定时器）。
- 跟弹**不进关卡计分**：旋律题主任务仍是听辨调性，跟弹是附加练习；网格落点、音长观察与曲库跟弹共用 `RhythmGrid` / `domain/hold.ts` 同一把尺子。

## 明确没有做的部分

- 没有搬参考项目的教师 CMS、云同步与班级/账号体系；也没有题库导入（乐理题目全由 `quiz.ts` 按 seed 生成，不是导入的题集）。曲库侧的 MusicXML 导入是另一个工具的职责，见 `docs/二期-曲目学习路径.md` §2.5。
- 普通练习仍是即时反馈 + 判读讲解，**不保存每次答题明细**；只有乐理地图的过关进度（`theoryPath`）与按题型的累计答数/答对数（`practiceStats`）写进 `Profile`。没有按题目的错题本，也没有正确率趋势图。
- 旋律题的主问题仍是「听调性」选择题。跟弹判音高（八度严格）、落点与音长（音长只作观察），不判力度，也没有麦克风录音比对。
- 弹奏作答同样不判力度；音型题的时值只作观察，不影响对错。
- 和弦进行题已按进行逐和弦谱面化（每和弦一小节全音符，`PracticeStaffPrompt.measures`），试听有「整组和弦」与「分解」两种；旋律题也已谱面化（见下「旋律谱面化」）。
