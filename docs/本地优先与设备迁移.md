# 本地优先与设备迁移

> 对应 TODO-13「账号与云同步」的 P2 决策。结论：**暂不做账号体系与云端同步，保持本地优先**；换设备用学习档案 JSON 手动迁移。

## 1. 为什么先做本地优先

- 当前产品的核心价值是识谱、视奏、曲库跟弹和练习反馈，不依赖跨设备实时同步。
- 引入账号/云同步会同时带来登录、隐私、托管成本、冲突合并和外部曲库包同步等一整套问题，超出当前阶段。
- 本地档案已经能完整导出/导入；对「换一台设备继续练」这个真实需求，手动迁移足够且可验证。
- README 的 MVP 非功能范围本来就写明不做云端同步；这里把 P2 的决策落成文档，而不是悄悄扩边界。

## 2. 换设备流程

1. 旧设备打开「我的 → 学习档案」，点「导出学习档案」，得到 `piano-buddy-backup-YYYY-MM-DD.json`。
2. 把 JSON 通过任意本地方式（U 盘、网盘、聊天工具）传到新设备。
3. 新设备打开「我的 → 学习档案」，点「导入学习档案」，选择该 JSON。
4. 界面先展示导入摘要，点「确认覆盖」后才写入；取消则保持当前档案不变。
5. 外部曲库包不在学习档案里；如果新设备需要这些曲目，重新导入对应的 `.pbpack` / `.json` 包。

## 3. 冲突策略

当前是**显式覆盖，不做自动合并**：

- 导入前必须经过二次确认，避免误覆盖。
- 确认后，导入档案替换当前 `Profile`；`mergeProfile` 只负责补齐旧版本缺少的字段，不会把两台设备的练习记录合并。
- 如果两台设备都练过，选一台作为主档案导出，另一台的增量不自动保留；需要保留时，先手动导出旧档案留底。
- 备份信封包含 `app`、`schemaVersion`、`appVersion`、`exportedAt`；版本不匹配或缺少 `profile` 的文件会被拒绝。
- 学习档案不含 IndexedDB 里的外部曲库包，避免把不可信包一起迁移。

## 4. 将来接云端的条件

只有在以下问题有明确答案后再开新的 TODO：

- 账号由谁提供，是否需要家长/教师角色；
- 数据存哪里，是否需要区域合规与删除机制；
- 冲突用「最后写入覆盖」还是按字段/练习记录合并；
- 外部曲库包是否随账号同步，如何做签名与来源校验。

在这些问题确定前，不把本地档案结构改成云端协议；现有 `Profile` 与备份信封保持可迁移即可。

## 5. 验收对应

- **换设备后档案可恢复**：导出 JSON → 新设备导入 → 确认覆盖后恢复学习进度。
- **冲突策略写进文档**：本文第 3 节。
- **不扩大 MVP 边界**：README 的「不做账号与云端同步」与本决策一致。
