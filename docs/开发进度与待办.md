## 4. 技术债与已知坑

| 现象 | 影响 | 建议 |
|---|---|---|
| **评级陷阱**：裸谱补指法后，求解器可能把 C 手位判成 D-shift，评级从 L3 抬到 L5 | 作者按「按音高」评级写 manifest 才不会被拒；界面无提示 | `import:batch` 已输出按音高/按指法差异表，`--strict` 会拦截差 ≥2 档；仍需人工改 `fingers`，不能靠改声明档绕过 |
| 连音线渲染假设「横向铺开不换行」 | 将来改成多行排版，跨小节曲线会画错 | `renderScore` 里 `drawStaveTies` 已注释清楚，改排版时同步拆成两条半截线 |
| 弱起只在首小节 | 中段弱起、反复内的弱起仍无法表达 | 反复结构已就位（TODO-05 ✅）；等真实曲目需要再补中段 `pickup` |
| 导入器不支持 `.mxl`（压缩包） | 用户需先另存为 `.musicxml` | 文档已写明；如需支持，解压后复用现有解析 |
| CI 不构建原生包 | `android/` / `ios/` 的编译错误要等本机构建才发现 | 需要时加一个 Android gradle 构建 job（要装 SDK，几分钟）；iOS 只能在 macOS runner 上做 |
| 移动端没有真机自动化 | BLE 连接在模拟器/CI 里跑不了，回归只能靠人工自检清单 | 已用假插件把「选通道→解码→分发→断线」全部测掉；真机只验证「系统授权 + 选择框」这一段 |
| headless 脚本依赖本机 chromium | 换机器需要改路径 | 已抽到 `scripts/lib/browser.mjs`，`PB_CHROME` 可覆盖；端口可用 `PB_PORT` / `PB_URL` 指定 |
| 外部包没有签名与来源校验 | 只能校验 manifest/路径/大小/checksum，无法阻止冒充或篡改后重新打包 | 当前仅本地导入；在线分发前再加签名、发布者白名单与撤销列表 |
| 两套练习口径并存：练习记录按「时长」，`practiceStats` 按「题数」 | 「我的」页两处数字对不上，容易被当成 bug | 在文案上分别标注「停留时长 / 答题数」，或合并成一张卡 |
| L6 有三首（《风铃》C、《疾风》C、《回廊》F），但都没有转位/七和弦与带连音的高难编配 | 高难度用户的织体选择仍单一 | 三首链路均已验收；下一首 L6 建议在 G 调或带转位和弦的跑动编配 |
| 小调只支持 a/e/d，对应曲目已齐（《雨巷》Am、《暮色》Em、《灯影》Dm） | 小调手位仍沿用大调五指位，没有单独的小调音阶课 | 三条小调各有教学曲后可观察是否需要开课；新调号（如 g/c 小调）仍要扩词汇表 |
| 增三和弦仍不在谱面词汇表（题库里有） | `C–E–G♯` 这类编配会被 `chordOk` 拒绝 | 增三在调内无法稳定拼写（同一和弦三种等音写法），等有明确教学需求再定口径 |
| 五音以上的和弦仍不支持（`maxChordSize` 最高 4） | 需要「八度重复 + 五音」的厚柱式和弦写不进来 | 现有编配用四音足够；真要开需连同 `fingering.ts` 的求解窗口一起扩 |
